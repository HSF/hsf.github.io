## Miscellaneous HSF matters

### HSF GitHub matters

Quick thoughts on [#1919](https://github.com/HSF/hsf.github.io/issues/1919).

Reviewed problems of some recently closed PRs by non-HSF people:
- PRs implement unnecessary changes.
- PRs implement unasked for changes (like addition of tools or web function we never discussed we needed).
- PR flooding of little changes.
- Accidental AI contribution in one case? PR deleted some text and didn’t match description of PR!

Thoughts: I don’t think AI is directly our problem. I don’t think a pull request template asking for the amount of AI used is addressing any problems. 

Plans:

Make a `CONTRIBUTING.md` for the HSF repo:
Meant to document GitHub repo contribution guidelines - link to it automatically displayed when someone opens an issue/PR + linked under a “Contributing” tab on the repo.
-> Makes any statement on our actual website unnecessary I think...

CONTRIBUTING.md content:
- Etiquette
- Due diligence 
- Good practice/considerations
- Reasons PRs may be rejected.

Questions discussed: 
- How useful is it to ask for indication if AI was used? We should be checking every PR regardless.
    - Other SG members find it useful. 
- Is it useful to require an issue be made first if improvements to webpage/general update across all pages want to be made?
    - General agreement.
- Is it useful for us to encourage contributions to open issues, if they’ve been assigned to other HSF members?
    - Yes - even if assigned.
